# 在线补丁安装器工作流

## 开发者视角

1. 用户开启 airmise 服务, 本机向公网暴露一个控制端口: `<public_host>:2192`
2. 开发者询问用户, 获取用户的公开地址后, 在开发者自己的机器上进入:

    ```sh
    strun 2190 depsland/gui/patch_maker_online/app.py -- \
        --debug \
        --developer-mode \
        --client-host <user_public_host> \
        --client-port 2192
    ```

    参数说明:
    - `--debug`: 可选

3. 开发者在自己的电脑的浏览器中访问 http://localhost:2190, 进入在线补丁安装器的控制台界面

    开发者会看到以下信息:
    - 用户的应用 id, 应用名称, 应用版本
    - 用户的应用资产清单
    - 用户正在使用的应用归属于哪个开发项目 (路径)

4. 开发者找到这个项目的 dist 目录, 对比下用户的应用版本和最新的版本是否一致, 如果不一致, 继续下面的操作
5. 将最新的版本的资产清单的绝对路径 (`<target_project>/dist/<appid>-<version>/source/.depsland/manifest.pkl`) 粘贴到 GUI 的 "Latest manifest file" 输入框
6. 点击分析按钮, 获得资产差异分析结果

    开发者可以根据需要选择哪些资产可以推送. 一般来说, 有以下技巧:
    - 对于流行的基于 C 的第三方库, 如果体积较大, 但是版本差异不大, 则排除.

        例如, 用户那边的 numpy 依赖是 2.2.0, 开发者这边的最新应用依赖了 2.2.1, 由于 numpy 体积较大, 开发者可以在评估风险后, 选择排除该依赖, 也就是不让 numpy@2.2.1 打入最终的补丁结果.

7. 对资产分析结果完成上述筛选后, 点击应用补丁按钮, 开始打补丁

    该操作会基于开发者选定的资产差异文件, 逐个推送到用户端.

    例如, "_新增_ A 文件(夹)" 会将开发者的 A 文件(夹) 推送到用户电脑的指定位置;

    "_覆盖_ B 文件(夹)" 会将开发者的 B 文件(夹) 覆写到用户电脑的指定位置;

    "_删除_ C 文件(夹)" 会从用户电脑上删除指定位置的文件(夹).

    以上操作会有备份动作[^1], 以避免严重错误.

8. 完成后, 开发者点击断开连接按钮, 然后告知用户已经升级完成, 用户可以关闭他的 airmise 服务进程, 并重新打开他的应用, 即可看到更新后的效果.

## 用户视角

> [!WARNING]
> 目前只完成了 "--developer-mode ON" 的功能, 纯用户角度的工作流暂未实现.

[^1]: 备份功能可能在 depsland v0.13.x 中完善.
